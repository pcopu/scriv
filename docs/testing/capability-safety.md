This extends rather than duplicates short-film's single successful cold reopening.
The existing whole proposal association 305961a0e71b90164d26 is too broad for this
witness: its network/outbox/credential assertions are explicitly not promoted.
The catalog limits capability links to successful owned preparation/validation,
retained-tree traversal and public status. Guards are mapped only on successful
admission, not as evidence of all their failure alternatives. Descriptor/inode,
permission and lock checks are implementation support for the externally observed
owned lifecycle; the journey does not independently observe OS metadata or prove
race resistance. No private file is read/written by the new witness.

## Exact excluded responsibilities and blockers

- approveOrigin is nil and no public command grants an origin. Unknown command
  is a dispatcher refusal, NOT execution of authorizeNetwork, validateLoopbackOrigin
  or authorizeOriginChange. HTTP/WebSocket/redirect rejection is excluded.
- No supported public token/outbox operation provisions credentials or arbitrary
  outbox records. Credential read/write/delete, outbox operations and 64 MiB/256-file
  bounds remain excluded. Advertised process-memory is not proof of Keychain
  nonaccess or credential erasure after an authenticated session.
- No host API accepts run/session IDs or arbitrary resume descriptors. Missing,
  invalid or reused IDs, mismatched root, corrupt marker, bad descendant modes,
  hardlinks/symlinks, depth/entry limits and lock contention cannot be deterministically
  driven here without forbidden injection/tampering. Positive traversal only.
- No pending-operation barrier or stale-response injection API exists. Timing a
  concurrent relaunch against a fast command would be nondeterministic; pending,
  timeout/uncertain, stale IDs and replay branches are excluded.
- Oversized raw protocol lines are silently discarded, so a timeout alone is not
  a distinguishing nonmutation oracle; excluded. Script-insert bounds and menu/
  observation limits require other focused fixtures and are not claimed here.
- Sensitive-input accessibility/OTP, native helper, cloud accounts and production
  preferences are untouched. No physical input or full interface parity claim.

The unchanged saved sample is a captured sentinel, not an independent fixture.
Only import envelope UUID/dates are nondeterministic in the custom fixture;
all other fields are independently expected. Fresh samples get new UUIDs from
ScrivProject defaults. A retained process starts on an unsaved sample; no Save
is issued before the old custom project is reopened. Every wait is read-only;
mutations are never retried. Final close leaves synthetic workspace files intact.
