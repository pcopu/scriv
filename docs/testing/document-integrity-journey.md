# Document integrity service journey

This document describes source behavior and verification requirements. It does not publish historical execution records or attest to a passing run.

Run through the actual public CLI with the trusted installed Tracer paths:

    SCRIV_TRACER_CLI=/absolute/tracer/bin/tracer.mjs SCRIV_TRACER_RUNTIME=/absolute/tracer/src/scenario-runtime.mjs node scripts/tracer-cli.mjs app -- test services document-integrity

The unchanged Worker is bundled and served on an ephemeral loopback port. The runner owns its process group, temporary HOME, D1, R2 and state; all outbound service requests are denied, metrics disabled, and inherited secrets/proxies/NODE_OPTIONS excluded. There is a 90-second process deadline, 5-second HTTP deadline, maximum 240 requests, 16 KiB request bodies and 64 KiB responses. Cleanup runs on normal completion and interruption.

Fixture actions before HTTP apply the three actual local D1 migrations, create synthetic owner/member/viewer/outsider identities and hashed sessions, and create a locally entitled synthetic team. No production state, external login, billing provider, R2 object or actual image bytes are provisioned. Fixtures are ephemeral and deliberately not a claim of authentication-provider or payment execution.

## Independently authored expectations

The input graph is authored in the journey, not generated by importing production models: one scene, one dialogue entry with one authored word and a canonical text link, one character with a digest-pinned portrait crop, one image with typed confirmed analysis, and one source-anchored cue. The complete saved item graph must exactly equal those authored inputs at version one, epoch one, sequence one and timing version one. Event changes must equal the same saved items; initial deletedItems must be empty.

Four actual leases are acquired. Nineteen deliberately invalid variants each receive an exact expected status/code and then a fresh snapshot and complete event stream. Active items and deletedItems including item versions, epoch, sequence, timing version and event payloads must remain exactly unchanged after each rejection. These include cross-entry duplicate word ownership, dangling text/analysis references, invalid typed region/decision/identity/confidence, portrait mismatch/digest/provenance, immutable byte count/captured prompt, three schema downgrades, and referenced-image deletion.

The final positive edit changes only editable image direction, character biography, entry color and cue label. Expected data is explicitly derived from those authored mutations, not from the server response. Four item versions advance to two, the scene remains at one, sequence advances to two, timing stays one, and the first event is unchanged. Final event after-items and receipt items each independently equal the expected four authored changed items, normalized by ID; deletedItems remains empty.

This is metadata and document validation only. It does not inspect pixels, run a provider analysis, claim recognition accuracy, exercise concurrency races, native UI, real accounts, maximum sizes, every enum or every immutable-image key.

V2 asserts initially empty tombstones, exact unchanged tombstones after all nineteen rejected mutations, empty tombstones after the valid edit, and separately compares final event and receipt after-items against authored expected changed items. ## Boundary and recovery continuation

After the connected graph is deleted and its exact replay verified, the same
public HTTP route restores all five items in one command. Expected data starts
from the independently authored graph and its explicit metadata edits. It also
contains a dialogue with NEL-separated words, an emoji and a retained BOM,
authored word timings, and an explicitly confirmed unlinked emoji range. The
complete item data, versions, timeline counter, event before/after items and
prior event history must match. Snapshot item order is normalized by ID;
receipt operation order and event change order are asserted separately.

Twenty-six rejected variants each require an exact status/code followed by an
unchanged public document snapshot and complete event stream:

- Blank character names and oversized aliases.
- Duplicate, overlapping, mismatched or unconfirmed text links, and both ways
  to split an emoji surrogate pair.
- Duplicate word identities, invalid timing provenance, overlapping word
  timings and spoken words in a direction.
- Unsafe image filenames and attempts to change six previously unexercised
  immutable image fields: version, filename, digest, MIME type, capture time
  and predecessor. Version/digest cases keep their analysis metadata consistent
  so they reach the immutability guard rather than an earlier analysis error.
- Unknown analysis kinds and negative completion timestamps.
- Unpaired cue anchors, coverage beyond the scene, mismatched resolved start,
  and a missing source entry.
- A two-item command with a valid character edit followed by a dangling entry
  reference. Neither edit, item version, event nor sequence may persist.

Repairing only that invalid reference while reusing the failed command ID must
succeed once. Both changed items, the receipt and the new event have independent
expected values. An exact replay must return the same receipt without changing
the saved document or event stream. The R2 bucket remains empty and no outbound
request may occur.

These are real local Worker HTTP assertions. They do not establish native UI,
physical input, live-provider behavior, lease-table internals, concurrent races,
crash durability, measured source-line coverage, or complete validation coverage.

## Dormant and overlapping image coverage

The timeline continuation creates a separate synthetic project through public
HTTP, reusing only the isolated actor/team fixtures. A zero-owned direction at
the end of an empty scene retains a 750 ms authored image extent while its
resolved cue is dormant at [0, 0]. Appending a 1,000 ms dialogue requires an
atomic cue edit to [0, 750]. Prepending a 500 ms direction moves the original
source and cue to [500, 1,250].

Five rejected edits require exact 409 codes and the complete unchanged document
snapshot excluding leases, plus the complete event history: a nonzero offset
into the zero-owned direction, an append without its cue update, legacy coverage
crossing the anchored cue from either
side, and deleting timed entries without updating their cues. The failed append
and collapse IDs are reused with only the necessary companion operations added.

A legacy cue ending exactly at 500 ms is accepted. Migrating it to a source
anchor permits the explicitly authored overlap [0, 750] with [500, 1,250]. The
journey then collapses the scene to the retained dormant cue, checks exact
metadata-only tombstones, and restores the dialogue and its resolved coverage.
Seven successful edits compare independently authored full items, ordered
receipts, versions, sequence/timing counters and complete event before/after
contents. Two exact replays must preserve the receipt, document snapshot
excluding leases, and complete history.

The 56 HTTP actions include public lease acquisition, reads and replays. The
declarative timeline catalog is navigation evidence, not an additional runtime
callback report. This chapter does not test the 24-hour scene limit, lease
expiry, native rendering/playback, crash recovery, concurrent edits, or measured
source coverage. It preserves the existing bounds, outbound-denial guard and
owned cleanup.
