# CLI image evidence, schema 1

`ScrivCLIImageEvidence.observe(workspace:windows:)` is a read-only, automation-build-only observer. The driver integrates it as `image-evidence` and advertises schema version 1. It takes no caller paths or job IDs. This source has **not been compiled or run in Catalyst**. Native validation remains blocked; this document does not establish live image, provider, preview, or build coverage.

## Boundary

Both `--scriv-cli` and `--screenshots` are required, together with a 36-character UUID `SCRIV_CLI_RUN_ID` and an exact `SCRIV_VERIFICATION_ROOT` matching the app temporary directory's `ScrivVerification-CLI-<lowercase UUID>`. Only jobs whose context names exactly `Projects/<project UUID>.scriv` under that root are selected. Their bounded persisted `project.json` must decode to the same project ID. Other jobs are omitted, not exported.

Reads anchor directly at the app-owned run directory or the controller’s already picker-authorized Generation directory, without opening `/` or unrelated ancestors for directory data access. The anchor must be canonical and a real directory; `lstat`, no-follow open, and `fstat` must agree on device/inode. Every relative descendant is traversed with directory descriptors and `O_NOFOLLOW`; final files must be regular and are opened with `O_NONBLOCK`. System temporary-directory prefix aliases are canonicalized before deriving the run anchor. Ancestor identity/access above the anchor relies on the app container or existing security-scoped picker grant. Canonical checks reject existing ancestor links but do not provide race-proof ancestor locking against concurrent replacement. This is not a root-wide descriptor traversal guarantee. Reads are bounded to 4 MiB for a project, 2 MiB for a journal, and 25 MiB for each image. At most 100 matching jobs are exported; a cache above 1,000 jobs fails closed. All errors are sanitized to a fixed string without paths.

Artifact location comes only from the real controller's `artifact(for:)`, never from request arguments or an independently supplied path. Its root must be this run's `Generation` or the controller's already-authorized external `Scriv/Generation` root. The latter is usable only after the application's existing explicit folder-picker authorization; this observer neither acquires access nor reads saved bookmarks. The job must still target this run's synthetic project. No generation journal is constructed, because its initializer creates directories and changes permissions.

For artifact-bearing jobs, the observer independently reads the exact journal and compares identity, context, status, output image ID, artifact path/hash, thread/turn IDs, and installation ownership against the actual controller. It then checks bounded bytes using the existing `validatedContents()` and its SHA-256 validation, in addition to a no-follow preflight read. Attachment evidence requires the persisted cue to reference the output image, the persisted asset's byte count and hash to agree, and package asset bytes to equal the artifact.

A fresh run with no jobs returns an empty `jobs` array. Before a job has artifact metadata, the public controller API has no read-only journal-root accessor. Those non-completed, unattached jobs return `journalVerified: false`, without artifact or asset evidence. They are observations of cached progress, **not verified terminal results**. A completed job without artifact metadata fails closed. A malformed or mismatched artifact-bearing job fails the whole observation rather than returning a partial pass.

## JSON fields

The envelope contains `schemaVersion: 1`, `runID`, and `jobs`.

Each job contains UUID-only `jobID` and `projectID`, plus `cueID` as nonempty metadata of at most 128 ASCII letters, digits, dots, underscores, or hyphens (for example `cue-01a`); the actual status enum; `hasThreadID` and `hasTurnID` booleans; `journalVerified`, `attachmentVerified`, `visiblePreviewCount`, and `previews`. If present, `outputImageID` and attached `assetID` must be UUIDs. Verified artifacts add `storedArtifactSHA256` and `artifact`. Verified persisted attachments add `asset`.

`artifact` and `asset` contain `sha256`, `byteCount`, `width`, `height`, `decodedThumbnailWidth`, and `decodedThumbnailHeight`. A single-frame ImageIO source must have positive dimensions no greater than 16,384 on either axis and no more than 40 million pixels. A forced, immediately cached thumbnail decode bounded to 256 pixels proves actual decodability; header dimensions alone are not accepted. Multiframe images are intentionally unsupported.

`previews` contains only visible `preview-picture` instances with `.loaded` state and a matching `loadedDigest`, actual UIImageView CGImage dimensions matching the validated asset, and a finite nonempty frame clipped through ancestors and the owning window. It is evaluated only when the actual workspace project path, project ID, selected/followed cue ID, and image ID match the persisted attachment. Only windows supplied by the driver are traversed; callers must pass its owned-window set. A preview behind its window's active modal is excluded. Records contain `windowIndex`, `loadedDigest`, `width`, `height`, and `frame` (`x`, `y`, `width`, `height`). This is structural loaded-preview evidence, not proof against arbitrary sibling/native-window occlusion; capture a separate synthetic screenshot for visual acceptance.

No prompts, titles, labels, error details, installation/account IDs, raw thread/turn IDs, authentication data, runtime paths, filenames, image bytes, or unrelated project content are returned. No network, attachment, repair, generation, or persistence action occurs.

## Acceptance still required

The driver must advertise the exact schema, reject unexpected arguments, and keep normal production builds excluded. Before a live turn, verify the observer against a real automation build including empty state, wrong run/root, symlink and special-file rejection, corrupted journal/hash, missing attachment, image bounds, and stale/hidden/covered preview cases. Those cases have not been executed here. A future live scenario must require completed status, independently verified journal and attachment, matching artifact/asset hashes, positive decoded dimensions, and a visible loaded preview. Source inspection or successful JSON output alone is not a live image pass. Existing one-turn approvals, credentials isolation, quota, telemetry, and standard-service prerequisites remain unchanged.
