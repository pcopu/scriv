# Synthetic billing service journey

`node scripts/tracer-cli.mjs app -- test services billing` exercises the real local Worker and billing/project Durable Objects over loopback HTTP, with synthetic identities, sessions, customer, events, subscription, project and team only. It does not use Stripe credentials, create accounts or perform real billing. The Worker has an explicitly configured in-process outbound service that accepts only one exact synthetic Stripe subscription-list request, returns deterministic fixture responses, and rejects/counts every other outbound request. The six expected provider attempts include a simulated outage and retry. This is simulated-provider service integration, not live Stripe acceptance or a zero-outbound-attempt test.

The sequence checks the owner-visible free plan, member and outsider authorization, invalid and expired webhook signatures, ignored event and unknown customer, active subscription reconciliation and member project access, duplicate receipt handling, cancellation and the resulting member read grace and write denial while the owner retains write access, delayed-event reconciliation against the current trialing provider state, a provider failure and same-event retry, and a wrong-price subscription that does not grant entitlement. Returned HTTP status, response fields and selected provider-attempt counts are asserted. The duplicate is followed by readback while the provider fixture has changed; the delayed event is followed by readback after fixture reactivation. Event creation times are synthetic. A read-grace result is only a recently canceled case, not a proof of behavior at or beyond 30 days.

The runner uses a private temporary home/state directory, sanitized child environment, disabled telemetry, bounded loopback requests/responses and a 90-second process-group deadline; owned state and processes are disposed on completion. It provisions initial synthetic data through a local D1 fixture before using HTTP for the journey. It does not test account login, checkout/portal success, live provider delivery or payment, native UI, deployment, or physical devices. The provider fixture is local and independent of application source.

Set `SCRIV_TRACER_RUNTIME` to the absolute path of `src/scenario-runtime.mjs` in the reviewed local Tracer package before running this selector or the unfiltered service suite. The reviewed offline tarball `pcopu-tracercli-0.3.0.tgz` has SHA-256 `3ed7a048ce7e2062b5ad947030f4af5f0a5130400009cf367d7d2e8b4d79602a`. The harness verifies the runtime and its imported local modules against pinned hashes; it neither vendors nor downloads the package. Set `SCRIV_TRACER_CLI` separately to the trusted local package's `bin/tracer.mjs` when Tracer is not on PATH.

`billing-steps.json` records ordered named actions, preconditions, and pinned assertion witnesses. Runtime outcomes are adapter-reported callback results, not measured execution or source-to-action proof. The integrated source mappings were independently reviewed as bounded static associations; they do not convert callback outcomes into measured source coverage.
