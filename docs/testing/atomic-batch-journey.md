# Atomic batch service journey

`node scripts/tracer-cli.mjs app -- test services atomic-batch` runs the real Worker and project Durable Object over isolated loopback HTTP. It seeds only synthetic identity, session and team fixtures. It denies Worker outbound requests, disables telemetry, bounds requests and responses, and disposes the owned process group and temporary state. This is not a live provider, native UI, or measured-coverage test.

Set `SCRIV_TRACER_RUNTIME` to the absolute path of `src/scenario-runtime.mjs` in the reviewed local Tracer package before running this selector or the unfiltered service suite. The trusted toolchain is the published Tracer tree `9f9964e22bfb77d9aad72aefac26f19706879e2c` at commit `8e12583bb8da60f9325a7cee5d1050b3b33aa679`. Use a verified local copy of that complete published tree; older packages with the same 0.3.0 version string do not identify these bytes. The journey verifies the runtime entry and its full local import chain (scenario-runtime, scenarios, tracer, catalog and proposals). No registry install, fallback or package vendoring is performed. Only this deliberately selected path enters the otherwise sanitized child environment.

The pinned `atomic-batch-steps.json` names ordered actions and assertion witnesses. The actual callbacks run HTTP and assertions; results printed by the runtime are adapter-reported callback outcomes, not line coverage or source-to-action proof. Reviewed source mappings provide declared navigation to relevant code and assertion witnesses; they do not turn callback outcomes into measured source coverage. The sequence covers a three-item two-part edit, immutable retries and conflicts, incomplete commits, a viewer denial, a second edit with an image and anchored cue, item-validation refusal and rollback after an invalid cross-item reference. It inspects state before and after failures and commits. Provider login, external services, physical devices and native acceptance are not exercised.
